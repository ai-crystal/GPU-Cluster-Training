# 附录 A　术语与缩写

按英文字母顺序排列。每条一行，只解释在这本书里的用法，不追求完整定义。同一个缩写在不同框架里含义不同的，按本书上下文给出。

**All-Gather**　集合通信原语，每个 rank 拿到所有 rank 数据拼接后的完整结果，FSDP 前向收集参数用它。

**All-Reduce**　集合通信原语，先对所有 rank 的数据求和，再把结果送回每个 rank，是梯度同步的基本操作。

**All-to-All**　集合通信原语，每个 rank 把不同的数据块发给不同的对端，MoE 的专家分发与收回各需要一次。

**Arithmetic Intensity**　算术强度，算子执行的浮点运算次数与搬运字节数之比，单位是每字节多少次浮点运算。

**Async Checkpoint**　异步检查点，先在显存或主机内存里做一份参数副本，再由后台线程落盘，把写盘移出关键路径。

**Attention**　注意力，序列中每个位置对所有位置加权求和的结构，计算量随序列长度平方增长。

**Backward Pass**　反向传播，从损失往回计算每层参数梯度，计算量约为前向的两倍。

**Bandwidth**　带宽，单位时间能搬运的字节数。显存带宽、节点内互联带宽、跨机带宽三者量级依次下降。

**BF16**　八位指数加七位尾数的半精度格式，范围与单精度相同但精度低，是目前预训练的主流精度。

**Bubble**　气泡，流水并行中某些级空闲的时间片，占比约 (p-1)/(m+p-1)，p 为级数，m 为微批次数。

**Bucket**　梯度桶，把多个参数的梯度拼成一块再一次性通信，用来摊薄启动开销。

**Burn-in**　烤机，机器上架后用压力测试跑几十小时，让早期失效的硬件在正式训练前就暴露。

**Capacity Factor**　容量因子，MoE 中每个专家允许接收的 token 上限相对平均值，超出的部分被丢弃。

**Checkpoint**　检查点，把参数与优化器状态落盘以便恢复。1750 亿参数按每参数 16 字节算约 2.8 TB。

**Chinchilla**　一组缩放规律结论，算力最优时每个参数配约 20 个 token。


**Compute-bound**　计算受限，算子时间由算力而非带宽决定，算术强度落在门槛右侧。

**Context Parallel**　上下文并行，沿序列维切分并让各卡轮流使用键值块，用于超长上下文训练。

**CUDA Graph**　把一串内核启动录制成图再整体重放，消除每步上百次启动的处理器开销。

**Data Parallel**　数据并行，每张卡持有完整模型副本、各跑一部分数据，反向结束后同步梯度。


**ECC**　纠错码，显存与链路上自动检测并纠正位错误的机制，可纠正错误计数是硬件退化的早期信号。

**Elastic Training**　弹性训练，允许作业在运行时增减节点，并按新的并行度重映射参数。

**Expert Parallel**　专家并行，把 MoE 的不同专家放到不同卡上，代价是每次都要做两次全对全通信。

**Fat-tree**　胖树，多层交换机构成的无阻塞或近无阻塞拓扑，上联与下联带宽之比称为收敛比。

**FlashAttention**　分块计算注意力并用在线 softmax 避免写出完整矩阵，显存占用从平方级降到线性级。

**FLOPs**　浮点运算次数。大写通常指总量，小写加 s 常指每秒次数，中文里混用严重，读时看上下文。

**FP8**　八位浮点，E4M3 与 E5M2 两种格式，训练时按张量或按块统计缩放因子。

**FSDP**　完全分片数据并行，前向收集参数、反向归约后立即释放，用通信换显存。

**Gang Scheduling**　成组调度，作业的所有进程要么同时启动要么都不启动，避免部分占用后互相等待。

**GEMM**　通用矩阵乘，训练里绝大部分算力都花在这类内核上。

**Gradient Accumulation**　梯度累积，多个微批的梯度相加后再更新一次参数，用时间换显存。

**Gradient Clipping**　梯度裁剪，按范数上限等比缩放梯度，防止单步更新过大。

**Grad Norm**　梯度范数，所有参数梯度拼成一个向量的长度，是训练稳定性的早期指标。

**HBM**　高带宽显存，H100 上是 80 GB、3.35 TB/s，是决定算术强度门槛的分母。

**HFU**　硬件浮点利用率，按含重计算在内的实际运算量计算，数值高于模型浮点利用率。

**Incast**　多打一拥塞，多张卡同时向同一目的地发数据，导致交换机缓冲区溢出和丢包。

**InfiniBand**　面向高性能计算的无损网络，单端口 400 Gb/s 折合 50 GB/s。

**IOPS**　每秒输入输出操作数，小文件与元数据密集场景的瓶颈指标。


**Loss Scale**　损失缩放，把损失乘一个系数以免低精度下梯度下溢，出现溢出时回退并跳过该步。

**Loss Spike**　损失尖峰，损失曲线突然上跳，可能来自数据、数值或硬件，需要按顺序排除。

**Master Weights**　主权重，优化器保存的单精度参数副本，更新后再转成低精度参与计算。

**Megatron-LM**　一套张量并行与流水并行的参考实现，后来的多数框架以它的数字为基线。

**MFU**　模型浮点利用率，实际达到的模型运算量除以峰值算力，公开的万卡训练在四成上下。

**Micro-batch**　微批，流水并行中一个级一次处理的样本数，同时决定气泡大小与激活内存。

**Mixed Precision**　混合精度，前向反向用低精度、参数更新用高精度，兼顾速度与数值稳定。

**MoE**　专家混合，每个 token 只激活少数专家，总参数量大而单 token 计算量小。

**NCCL**　NVIDIA 集合通信库，按拓扑建图并选择算法、协议与通道数，行为由一组环境变量控制。

**NDR**　InfiniBand 的一代速率，单端口 400 Gb/s，即 50 GB/s。

**NVLink**　节点内 GPU 互联，H100 上单向 900 GB/s，是跨机带宽的十几倍。

**NVSwitch**　节点内把多张 GPU 全互联的交换芯片，让任意两张卡之间都跑在 NVLink 速率上。

**Offload**　卸载，把参数或优化器状态搬到主机内存或本地盘，用带宽换显存。

**Optimizer State**　优化器状态，Adam 的一阶与二阶矩，每参数 8 字节，通常是显存占用的最大项。

**Overlap**　重叠，把通信与计算放在不同流上并行执行，是万卡规模效率的主要来源。

**PFC**　优先级流控，链路拥塞时发暂停帧，扩散开来会形成暂停风暴，影响整个广播域。

**Pipeline Parallel**　流水并行，按层切分模型并让不同级处理不同微批，代价是气泡。

**Preemption**　抢占，调度器回收正在运行的资源，依赖检查点才不会丢失进度。

**Profiling**　性能剖析，记录时间线与内核细节以定位瓶颈，分系统级与单内核两级。

**Rank**　进程编号，分布式作业里每个进程的唯一标识，也是日志与指标的基本维度。

**RDMA**　远程直接内存访问，绕过对端处理器直接读写内存，是跨机通信低延迟的前提。

**Recomputation**　重计算，前向不保存激活、反向时重算，用算力换显存，通常多花约三分之一计算量。

**Reduce-Scatter**　集合通信原语，先归约再按 rank 切分结果，是 ZeRO 与 FSDP 的核心操作。

**Ring All-Reduce**　环状全归约，传输量为数据字节的两倍乘以 (N-1)/N，大消息时接近最优。

**RoCE**　在以太网上承载远程直接内存访问，依赖无损配置与流控，配置不当会出现长尾。

**Roofline**　一种把算力上限与带宽上限画成折线的模型，用来判断算子受哪一侧限制。

**SDC**　静默数据损坏，计算结果错了但没有任何报错，只能靠校验和与抽取重算发现。

**Sequence Parallel**　序列并行，沿序列维切分 LayerNorm 与 Dropout，减少张量并行的重复存储。

**Sharding**　分片，把参数、梯度或优化器状态切到多张卡上，是 ZeRO 与 FSDP 的共同思路。

**SM**　流多处理器，GPU 的基本执行单元，H100 有 132 个，占用率与并行度都由它决定。

**Step Time**　步时，一次参数更新花掉的墙钟时间，它的倒数就是每秒步数。

**Straggler**　掉队者，比同伴慢的节点或进程，在同步训练里直接决定整体速度。

**Strong Scaling**　强扩展，总工作量固定、增加卡数，衡量时间能降到什么程度。

**Tensor Core**　张量核心，执行小矩阵乘加指令的专用单元，是峰值算力的主要来源。

**Tensor Parallel**　张量并行，把单层内的矩阵切到多张卡，每层前向反向各一次全归约。

**TMA**　张量内存加速器，异步把大块数据搬进共享内存，不占用寄存器。

**Warmup**　预热，训练初期逐步提高学习率；也包括重启后重建缓存与通信组的那段时间。

**Weak Scaling**　弱扩展，每卡工作量固定、增加卡数，衡量步时能否保持不变。

**World Size**　全局进程数，通常等于总卡数，是所有并行度的乘积。

**XID**　驱动报出的错误码，用于区分落卡、显存错误、链路训练失败等硬件故障。

**ZeRO**　零冗余优化器，分三阶段切分优化器状态、梯度与参数，显存最多可降约八倍。

**Zero Bubble**　零气泡调度，把反向拆成输入梯度与权重梯度两部分，用一部分填另一部分的空。
