# 后记

写这本书的过程中，有一个数字反复出现：四十亿亿亿亿分之一秒。

它是光在 3 纳秒里走过的距离，也是万卡集群里一次跨节点往返的量级。当你把模型切到一千张卡上，一次梯度同步就要在这样的时间尺度上完成几百次。物理规律不会因为软件优化而让步，这也是为什么集群的规模越大，工程师越要对“数据在哪里、要走多远”保持敏感。

大规模训练的历史并不长。2018 年的 BERT 用 64 张 TPU 跑了几天，2020 年的 GPT-3 用上千张 V100 训练了几个月，2024 年的 Llama 3 用一万六千张 H100 跑了五十四天。六年间，集群规模涨了二十多倍，单卡算力涨了十几倍，软件的复杂度涨得更快。今天一个人要想独立复现一次前沿规模的训练，几乎不可能，但这不妨碍我们理解它是怎么运转的。

理解了之后，很多看似神奇的数字会变得平常。MFU 40% 不是厂商吹嘘的营销数字，而是计算、访存、通信三者平衡之后的结果。一次训练中断也不是灾难，只要检查点足够新、恢复流程足够熟练，它就只是账本上的一行时间。

如果这本书只能留下一个结论，我希望是这个：大规模训练的性能，最终由最慢的那个环节决定，而不是最快的那个。找到那个环节，比优化任何一个局部都重要。
